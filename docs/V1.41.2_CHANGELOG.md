# 1.41.2 — vivo V2199A / Android 14 后台计时优化与分线程诊断

## 依据与边界

1.41.1 用户日志：exactAlarm=true、batteryExempt=true，PID 始终为 5635，主线程心跳长时间消失，没有 alarm_received；打开应用后才出现 ViewModel 结束请求、服务结束与音频启动。处理迟到约 70 分 45 秒。

这支持调查后台冻结、设备休眠或主线程阻塞，但不证明某一项是唯一根因。WakeLock.isHeld=true 不证明进程在持续执行，也不证明厂商策略未限制应用。此版不是“已保证提醒必达”的版本。

## 已改动

### 减少主线程阻塞风险
- 服务音频操作归属独立 `timer-media` HandlerThread。
- 静音保活播放器用 prepareAsync，而不是主线程同步 prepare；准备超时/错误有日志和回收路径。
- 保留前台服务、MediaSession、静音保活、WakeLock 和精确闹钟，不改成依赖 UI 的计时。
- 结束时先发起震动请求，再在媒体线程准备、播放铃声，音频文件准备不再直接阻塞服务主线程。
- 播放请求带代次检查：排队的旧结束播放在停止或新座次后失效，准备完成后再次检查。播放器操作串行，不从主线程并发操作同一播放器。
- 服务结束时回收探针与媒体线程；探针不另外持有 WakeLock，不再创建第二个提醒计时器。

### 闹钟交接
- 安般念自然结束时，ViewModel 不先取消系统闹钟；提醒服务接手后取消。手动完成、暂停、重置仍取消。
- 经行自然结束的取消职责也留给服务。
- 熄屏不再重复注册相同结束闹钟；同一进程内同一期限注册成功后，重复 schedule 不替换原闹钟。
- 去重只保存在进程内，不把 SharedPreferences 或 PendingIntent 的存在误当成系统闹钟仍已注册；新进程/重启可重新注册。
- 没有额外添加重复 AlarmManager 闹钟，也不通过隐藏负数掩盖执行故障。

### 新诊断
- 所有事件包含墙钟、elapsedRealtime、uptimeMillis、线程名、PID。
- 独立 timer-probe 线程每 30 秒采样并投递一个主线程确认；始终至多一个未确认回调。
- 记录 elapsedGapMs、uptimeGapMs、sleepGapMs、mainAckAgeMs；停止时再记录 probe_final，尽量保留恢复前台的最后一段空白。
- 主线程确认长时间未返回时，最多每 5 分钟记录一次不超过 16 帧的主线程栈。
- 记录交互/Doze/省电/后台受限/待机分桶状态。nextSystemAlarm 是全设备的下一闹钟，不证明归属于本应用。
- 诊断仍只保存本地轮换文件，用户主动复制后才分享；包含技术栈及设备状态，不保存修习笔记。

解释注意：
- probe 继续而主线程确认停止：更支持主线程阻塞，结合栈判断。
- 两者都出现长空白：支持进程整体未执行/调度受限等方向，但不能仅据此确定厂商冻结。
- elapsed 增量远大于 uptime：说明期间存在深度休眠；探针不可能在被冻结期间自行记录冻结原因。
- 诊断写入线程或系统状态 Binder 调用本身也可能被延迟，仍需系统证据交叉判断。

## 验证结果

- Kotlin 2.0.21 编译器直接编译 `TimerDeadline`、`TimerProbeSample` 与对应测试，JUnit 4.13.2 运行 **10 个测试全部通过**。测试覆盖期限恢复、取消/过期匹配、最后一次检查边界、正常间隔/休眠/长调度空白/时钟回退。
- `perl tools/static_checks.pl` 通过：91 个 Kotlin 文件的词法括号、既有滚动策略、AlarmReceiver 接线、异步媒体与交接源码约束。
- 以上不是 Android 全工程编译或真机验证。没有 Android SDK，本轮未恢复用户已清理的 Gradle 环境；未产出 APK。
- 编译器测试工具放在 `/tmp/ruru-kotlin-check`，不打入工程压缩包。

## 验收

1. 编译安装 1.41.2（1412），计时卡片“复制计时诊断”显示 1.41.2。
2. 同样设置下先做 5–10 分钟锁屏，再做真实 60 分钟；两者需要分别验证，短时成功不证明长时可靠。
3. 保持测试条件一致（充电状态、是否中途解锁、vivo 自启动/后台高耗电设置），记录改变过的设置。
4. 失败后复制日志；若具备电脑，优先在 **尚未打开应用** 时运行 `sh tools/capture_timer_state.sh`，保存闹钟、服务、进程、电源与诊断 logcat 状态。该脚本不启动应用、不修改系统设置；USB 调试连接本身可能影响休眠，应标明测试方式。系统转储可能含其他应用元数据，分享前审阅。
5. 暂停跨原期限、恢复、更换时长、手动结束、确认出定、切换页面/进程恢复，必须检查无旧铃声误响、无重复历史。
6. 如整进程后台受限仍存在，不继续无限叠加线程或锁；结合系统证据和 vivo 对该应用的后台策略处理。验证通过前使用独立系统闹钟兜底。
