# 1.41.1：Android 14 锁屏到点未提醒的定向修复与诊断

## 用户复现
安装上一版源码重新编译的 APK，设定安般念 60 分钟。在 Android 14 上锁屏到点无铃声、无震动，系统通知倒数变负数；打开应用后才播放铃声、震动并显示结束。
此现象将排查重点指向后台交付/执行，但不能仅凭现象区分厂商冻结、闹钟未交付、服务启动失败和服务内部失败。无该手机运行日志，尚未确认唯一根因。

## 修改
- versionName 1.41.1 / versionCode 1411，便于确认安装版本。
- 安般念 AlarmManager 由直接启动前台服务改成显式 BroadcastReceiver，仍使用一个 setAlarmClock，失败时尝试 setExactAndAllowWhileIdle；不增加重复闹钟。
- Receiver 检查结束期限，忽略暂停、取消、换座后失效的请求。
- 接收器调用服务前获取最多 60 秒的部分唤醒锁；不在 onReceive 返回时立即释放，而是在服务接手后释放。进程死亡不能靠这把锁保证恢复，超时也不能保证服务被厂商允许执行。
- Receiver 不发布 UI 完成事件，完成事件由服务播放处理后发布。
- 升级时清理旧版本 direct-service PendingIntent，避免双重结束路径。
- 媒体状态或通知更新失败不直接跳过铃声、振动；创建媒体会话失败不阻止服务进入命令处理。
- 每分钟记录服务心跳，以及闹钟注册、接收延迟、服务指令、到点处理、播放启动结果、振动请求、Activity 返回前台等诊断事件。
- 诊断文件在单独线程写入，单文件约 128 KiB 轮换，最多保留当前及上一份；仅本地保存，不自动上传，不含修习笔记或音频路径。
- 安般念卡片提供“复制计时诊断（1.41.1）”，包含版本、品牌型号、Android 版本、精确闹钟/电池优化豁免状态及事件。用户可自行粘贴反馈。

## 验证
- `perl tools/static_checks.pl` 通过（88 个 Kotlin 文件括号检查、滚动策略、闹钟接线源码约束），不是 Android 编译或运行测试。
- 添加期限匹配/取消/过期请求单元测试，尚未运行。
- 本轮未重新安装用户已要求清理的 Gradle 环境，也未完成 APK 构建；当前无 Android SDK。源码包不能当作已验证 APK。
- 尚未真机验证是否解决该设备的后台故障，不承诺后台提醒必达。

## 复测
1. 编译安装此工程，确认卡片按钮包含 1.41.1。覆盖安装后先结束旧座次，再开始新测试。
2. 先做短时锁屏提醒测试，再做一次真实 60 分钟锁屏测试；短时成功不能证明长时后台可靠。
3. 若仍不响，记录到点时刻、是否解锁才响或必须进入 App 才响；进入后复制计时诊断。记录手机品牌、型号与系统版本。
4. 核对日志顺序：alarm_scheduled → alarm_received → alarm_service_requested → service_command → end_begin → end_audio_started / end_vibration_requested。service_requested 只代表提交请求，不代表已执行；vibration_requested 不代表设备实际振动。
5. 测试暂停跨旧期限、恢复、手动结束、重复闹钟、通知确认出定，不应误响或重复保存记录。
6. 系统设置允许通知、闹钟权限、后台运行；厂商“自启动/后台高耗电/无限制”选项按机型核实。不要将故障未经诊断就归因于用户权限。
7. 修复实测通过前，长时间修习同时使用独立系统闹钟。
