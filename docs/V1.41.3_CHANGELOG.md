# 1.41.3 — 按座次归档、增强诊断及 ZIP 导出

## 目标与边界
保留已在用户 vivo 后台设置调整后成功的 1.41.2 计时结构，本版主要增强可观测性，不再叠加保活措施。不能承诺收集所有故障原因：进程被冻结/杀死时不能继续记日志，OEM 内部策略也未向普通应用开放。系统现场仍可用 tools/capture_timer_state.sh 在电脑采集。

## 按座次归档
- 安般念、经行新计时分配 timestamp_kind_random ID；暂停继续不换 ID，ID 保存本地供进程恢复沿用。
- 技术事件含 app 版本、PID、线程、wall time / elapsedRealtime / uptime、session ID。
- 保存最近十个非保护座次，以及两个计时类别当前/最近的座次。每座次两个 512KiB 分段；发生淘汰会写 TRUNCATED.txt，不假装记录完整。
- 异步串行写文件，队列最多 2048 个待处理事件，超出后记录 DIAGNOSTIC_EVENTS_DROPPED；存储失败写 logcat 并在后续恢复时报告丢失计数。
- 旧 1.41.2 日志不删除，导出时放入 legacy/；新日志放 sessions/。
- 异步环境查询含 requestedAt / capturedAt，避免把返回前台的系统状态当作冻结期间状态。

## 新增/完善的信息
- App 进程创建、Activity resumed/paused/stopped。
- 用户暂停、继续、手动完成、重置、确认提醒，计时恢复状态。
- 闹钟注册/取消/接收及迟到量，服务 action/flags/startId，结束来源：service_tick / system_alarm / viewmodel_request / screen_on / screen_off。
- 服务创建销毁、任务划除、内存回收通知、WakeLock 获取与释放。
- 屏幕亮灭、解锁、插拔电源、Doze/省电变化、系统时间及时区变化（服务存活时接收）。
- 型号/系统显示版本、时区、启动计数、精确闹钟/通知/电池豁免、后台受限/待机桶状态。
- 电量、充电状态、温度、系统闹钟音量/媒体音量、振铃模式、勿扰过滤状态、通知渠道重要性。
- 音频来源仅 custom/builtin，不含文件名路径；焦点请求结果、启动、完成、运行错误、回退内置与停止。
- 震动设备可用性、开关跳过、API 返回、主路径/回退失败；不能用 API 返回证明用户实际感受到震动。
- 异常类别、有限原因链和调用栈；不保存异常 message，避免系统文档提供者错误带出用户音频路径。
- 导出时读取系统可提供的最近八条本应用进程退出原因（Android 11+），不保证系统会保存每次记录，不读取 trace 内容。
- 探针增加 ackPending 和 lastAckLatencyMs，防止把正常 30 秒采样误读为主线程卡顿。
- 系统环境查询在独立有界任务队列运行，不阻塞探针采样；若系统查询堵塞，记录 snapshot_skipped。

## 导出及隐私
安般念计时卡片：
1. “导出计时诊断 ZIP（1.41.3）”：系统保存对话框选择位置，之后上传该 ZIP；无额外全盘文件权限，无自动上传。
2. “复制最近计时摘要”：仅最近一座末尾最多 18000 字符，明确不是完整报告。

ZIP 包含 report.txt（标注为导出时状态）、README.txt、sessions/、legacy/。
数据不含修习笔记、音频内容、联系人、设备唯一标识。设备型号、事件时间、技术栈和历史进程状态仍可能敏感，分享前审阅。旧日志可能带此前版本的异常文字。

OEM 自启动、后台高耗电、暂停闲置应用设置标为 UNKNOWN；不能用标准权限 true 冒充已核实这些设置。反馈时请人工补充设置及屏幕/充电操作。未读取其他 App 的日志或私有数据。

## 验证
- Kotlin 2.0.21 + JUnit 4.13.2：15 项实际测试通过（含座次隔离、分段轮换/丢失标记、保留策略、摘要截断提示和目录穿越拒绝）。
- 93 个 Kotlin 文件的静态约束/词法括号检查通过。
- TimerDiagnostics、TimerExecutionProbe、DiagnosticStore、ExactAlarmPermission 及音频两类完成针对 Android 14 API jar 的局部 Kotlin 类型检查。BuildConfig、R、Hilt 注解、NotificationManagerCompat 等使用替代声明，因此这不是完整构建。
- 未做 Android 全工程编译、Compose 导出界面运行或真机 ZIP 导出验收，未产出 APK。

## 真机验收
- 开始两座、暂停/继续一座、进程恢复、经行与安般念分别测试，检查分组/事件没有混淆。
- 完成后导出 ZIP，核对 events 起止、版本和 report；无 storage 权限时应能用系统文件选择器保存。
- 同时调整屏幕、充电、音量，核对历史快照与导出时快照不混同。
- 若选择取消保存、不支持写入的云盘或空间不足，应提示导出失败/不完整，不提示已保存。
- 保持已验证可用的 vivo 后台设置。日志增强不是要求重新关闭有效设置做风险测试。
